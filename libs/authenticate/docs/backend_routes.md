# Backend Routes

Notes:

- Endpoints accept both form and query parameters. Parameters are read from
  `:params`, `:body`, `:body-params`, `:json-params`, `:form-params`, and
  `:query-params`, in that order. Parameter keys may be keywords or strings.

- Check the [schema](schema.md) for details about configuration keys.
  Configuration keys must be set on the Ring request map.

## Send signin code

`POST /_biff/auth/send-code`

Sends a signin code to the given email address. Captcha-protected. Works for new
users and existing users. Parameters:

```clojure
:email  ; The user's email address. Required.
```

Whatever parameters your captcha provider needs are also required.

Configuration:

```clojure
:biff.auth/captcha-param
:biff.auth/captcha-verify
:biff.auth/code-page
:biff.auth/email-validated
:biff.auth/send-email
:biff.core/kv-set
```

Redirects to the code page (`:biff.auth/code-page`) with the following
query parameters:

- `email={email}` on success.
- `error=invalid-email` if `:biff.auth/email-validated` returned false.
- `error=captcha` if the captcha test failed.
- `error=send-failed` if `:biff.auth/send-email` returned false.

Any additional parameters are saved so they can later be provided to
`:biff.auth/create-user`. See [verify signin code](#verify-signin-code).

## Verify signin code

`POST /_biff/auth/verify-code`

Verifies a signin code for the given email address. Parameters:

```clojure
:email  ; The user's email address. Required.
:code   ; The signin code. Required.
```

Configuration:

```clojure
:biff.auth/app-path
:biff.auth/code-expiry-minutes
:biff.auth/code-page
:biff.auth/create-user
:biff.auth/get-user-id
:biff.auth/max-failed-attempts
:biff.core/kv-get
:biff.core/kv-set
```

On success, redirects to `:biff.auth/app-path` and stores the user ID at `:uid`
on the session. For new users, the saved parameters from the [send signin
code](#send-signin-code) request are passed to `:biff.auth/create-user`.

On failure, the request redirects to the code page (`:biff.auth/code-page`)
with these query parameters:

```text
email={email}&error=invalid-code
```

## Verify signin link

`GET /_biff/auth/verify-link/:payload`

Verifies a signin link (payload). This link is generated by [send signin
link](#send-signin-link);

Configuration:

```clojure
:biff.auth/app-path
:biff.auth/create-user
:biff.auth/get-user-id
:biff.auth/link-expiry-minutes
:biff.auth/link-page
:biff.auth/verify-link-page
:biff.core/kv-get
:biff.core/kv-set
```

If the link is opened in the same browser that requested it and the payload is
valid, redirects to `:biff.auth/app-path` and stores the user ID at `:uid`
on the session. For new users, the saved parameters from the [send signin
code](#send-signin-code) request are passed to `:biff.auth/create-user`.

If the payload is valid but the link was opened on a different browser,
redirects to `:biff.auth/verify-link-page` with the `token` query parameter set.
See [confirm signin link](#confirm-signin-link).

 Otherwise, redirects to 

the user is signed in. The request redirects to `:biff.auth/app-path` and
stores the user ID at `:uid` on the session. For new users, the saved parameters
from the [send signin link](#send-signin-link) request are passed to
`:biff.auth/create-user`.

If the link is opened in a different browser, the request redirects to the
verify link page (`:biff.auth/verify-link-page`) with this query parameter:

```text
token={token}
```

The verify link page should ask the user for their email address and submit it,
along with the token, to [confirm signin link](#confirm-signin-link).

If the link is invalid or expired, the request redirects to the link page
(`:biff.auth/link-page`) with this query parameter:

```text
error=invalid-link
```
